![エディタでそのまま開いた Markdown と、mdMirror で開いた同じファイルの比較](/images/mdmirror/01-hero.png)
*同じ `.md` ファイルです。左がそのまま開いたところ、右が右クリック →「mdMirror で開く」*

AI に書かせた設計書・調査ログ・仕様の下書きが、`.md` のまま溜まっていませんか。

書かせた直後はチャット画面で整形されて読めます。ところがファイルとして保存した瞬間、それは**記号の混じった素のテキスト**に戻ります。`##` と `|---|` と `- [ ]` が並ぶ画面を、人間はあまり読み返しません。読み返さないので、AI が何を書いたのか誰も把握していない、という状態が普通に起きます。

かといって「読みやすいように独自記法を足す」ことはできません。そのファイルは AI がこの先も読み書きし続けるので、**ソースは標準の Markdown のままである必要がある**からです。

そこで、方針を一点に絞ったビューアを作りました。

> ソース（`.md`）は 1 バイトも変更しない。読みやすさは**表示側だけ**で足す。

- `.md` を右クリック →「**mdMirror で開く**」で、既定のブラウザに整形して表示する
- ファイルは変換もコピーもしない。**元の Markdown には触らない**
- 常駐しない・サーバを立てない・外部通信しない・npm も要らない・管理者権限も要らない

https://github.com/thirtypower/mdMirror

MIT License です。Windows 10 / 11 で動きます。

## そもそも Windows で `.md` を開くと何が起きるか

`.md` ファイルは Windows の標準では何にも関連付けられていません。ダブルクリックすると「このファイルを開く方法を選んでください」が出るか、メモ帳が開いて記号がそのまま表示されます。だいたい次のどれかに落ち着くはずです。

| 開き方 | 結果 | つらいところ |
|---|---|---|
| メモ帳 / 既定のテキストエディタ | 素のテキスト | 記号のまま。表も図も読めない |
| ブラウザにドラッグ&ドロップ | 素のテキスト | ブラウザは Markdown を解釈しない |
| VS Code のプレビュー | きれいに読める | 「まず VS Code でフォルダを開く」が必要。ざっと読むには大げさ |
| ブラウザ拡張のビューア | きれいに読める | ローカルファイルへのアクセス許可が要る。フォルダ横断はできない |
| 変換系ツール（HTML / PDF 出力） | きれいに読める | 出力ファイルが増える。元を直すたびに変換し直す |

要するに「**エクスプローラで見つけた `.md` を、その場で、今すぐ、読みたいだけ**」という一番多い用途に、ちょうどいいものが見当たりませんでした。mdMirror はそこだけを狙っています。

## 実際の表示

ここからが本題です。ソースは全部、AI が普通に書く Markdown のままです。

### 表は表として、進捗は進捗として見える

![数値表のセル内バーとチェックリストの進捗バー](/images/mdmirror/02-table.png)

数値だけの列は自動で右寄せになり、**セルの中に大小がバーで出ます**。見出しをクリックすればソートもできます。`- [x]` のチェックリストには進捗バーが付きます（この例だと `3 / 6 完了`）。

ソース側は、ただの Markdown の表と、ただの `- [x]` です。

```markdown
| 項目 | 現状 | 目標 | 達成率 |
|---|---|---|---|
| ピーク時 rps | 180 | 400 | 45 |
| 平均応答 (ms) | 240 | 120 | 50 |

- [x] フェーズ 0: 配送テーブルの棚卸し
- [ ] フェーズ 2: 直参照経路の遮断
```

画像の中の緑と黄色のボックスも同じ考え方です。`重要:` `注意:` `ヒント:` `TODO:` で始まる段落を、表示側が色付きのコールアウトにしています。**ソースはただの段落のまま**なので、AI から見れば何も変わっていません。人間から見ると目立ちます。GitHub 記法の `> [!NOTE]` にも対応しています。

### mermaid はそのまま図になる

![mermaid のシーケンス図が描画されている画面](/images/mdmirror/03-mermaid.png)

` ```mermaid ` のコードブロックは図として描画されます。ズームとパンができるので、大きいフローチャートでも潰れません。mermaid 本体は同梱してあるので、**CDN も社内プロキシも関係なく描画されます**。

### フォルダごと開いて、横断で全文検索

![フォルダ内の 5 ファイルを横断検索している画面](/images/mdmirror/04-search.png)

フォルダを右クリックして開くと、その中の `.md` がまとめて読み込まれます。左のボックスに打つと**フォルダ内の全ファイルを横断して検索**でき、ヒット行と行番号がその場に出ます。

`docs/` に 20 個も `.md` が溜まったあとで「キャッシュの話ってどこに書いたっけ」を解決するのは、だいたいこれです。`.md` 同士のリンクもそのまま辿れて、ブラウザの「戻る」が効きます。

### ダークテーマ・コードハイライト・目次

![ダークテーマでコードブロックがハイライトされている画面](/images/mdmirror/05-dark.png)

ライト / ダーク、文字サイズ、表示幅、読書位置を覚えます。コードブロックの構文ハイライトは自前実装で、これも外部ライブラリなしです。見出しからは目次が自動生成され、スクロールに追従します。

## 書き手（＝AI）は何も変えなくていい

まとめると、こういう対応です。左はごく普通の Markdown です。

| ソースの書き方 | 表示 |
|---|---|
| `注意:` `重要:` `TODO:` `ヒント:` で始まる段落 | 色付きのコールアウト |
| `> [!NOTE]` | 同上（GitHub 記法） |
| 数値だけの列がある表 | 右寄せ＋セル内バー＋見出しクリックでソート |
| `- [x]` のチェックリスト | チェックボックス＋進捗バー |
| ` ```mermaid ` | 図として描画（ズーム・パン可） |
| ` ```sql ` ` ```csharp ` など | 構文ハイライト |
| 見出し | 目次を自動生成＋スクロール追従 |
| 画像 | 元の場所を参照（コピーしない） |

`CLAUDE.md` や AI 向けの指示ファイルに「こう書け」と足す必要はありません。**すでにあるファイルをそのまま開くだけ**です。

## 導入

1. GitHub の緑の **Code** ボタン →「Download ZIP」で取得して展開する
2. 展開したフォルダを、どこでもよいので置きたい場所に置く（例: `C:\tools\mdMirror`）
3. `install.cmd` をダブルクリックする

これだけです。インストーラも npm も要りません。

:::message
ZIP で受け取ったファイルには Windows が「別の PC から来た」印を付けます。展開する**前**に ZIP を右クリック →「プロパティ」→ 下部の「許可する」にチェックを入れてください。
:::

:::message
Windows 11 の右クリックメニューは表示数が絞られているので、項目は「その他のオプションを表示」の中に入ります。`Shift` を押しながら右クリックすると最初から出ます。
:::

`.md` の「既定のアプリ」は変更しません。ダブルクリックでエディタが開く動作はそのままです。

やめるときは `uninstall.cmd` を実行して、フォルダを削除するだけです。レジストリは `HKCU`（自分のユーザー分）しか触らないので、管理者権限も要りません。

## 仕組み

構成は単純です。

```mermaid
flowchart LR
  A[".md / フォルダを<br/>右クリック"] --> B["mdm.exe"]
  B --> C["フォルダを走査し<br/>本文を集める"]
  C --> D["index.html に<br/>データを埋め込む"]
  D --> E["%TEMP% に<br/>一時 HTML を出力"]
  E --> F["既定のブラウザで開く"]
```

ビューア本体は `index.html` **1 ファイル**です。Markdown パーサも構文ハイライトも自前で、外部ライブラリは mermaid だけ。その mermaid も同梱してあるので、通信は一切発生しません。

ランチャー（`mdm.exe`）がやるのは、対象フォルダの `.md` を集めて `index.html` に埋め込み、`%TEMP%` に置いてブラウザに渡すことだけです。**ブラウザは静的なファイルを開いているだけ**なので、ローカルサーバも常駐プロセスも要りません。開き終われば何も動いていません。

`mdm.exe` は Windows に同梱されているコンパイラ（`csc.exe`）で C# のソースからビルドします。これをやっているのが `install.cmd` です。つまり**リポジトリに exe を置いていません**。実行ファイルを配らずに済み、受け取る側に用意させるものもありません。

:::details なぜ PowerShell スクリプトではなく exe なのか
最初は PowerShell スクリプトでした。2 つの理由で C# に移しました。

1. **黒い窓が出る**。`powershell.exe` はコンソールサブシステムなので、Windows がプロセス起動時にコンソールを先に割り当てます。`-WindowStyle Hidden` は PowerShell 自身が起動してから効くので、その一瞬だけ黒い窓が見えます。引数では消せません
2. **起動が遅い**。PowerShell 5.1 はプロセスの起動だけで 181ms。`mdm.exe` は 5ms でした

右クリックしてから表示までの体感は、ほぼここで決まります。
:::

### 一番効いた工夫：同じ内容なら書き直さない

作っている途中で一番はまったのがこれでした。同じ文書を開き直すだけで **2〜5 秒**待たされる、という現象です。

原因はウイルス対策ソフトでした。Windows Defender は**書き込み直後のファイルを検査し、検査が終わるまで、次にそのファイルを開く側を待たせます**。生成処理そのものは 40ms 以下なので、待ち時間のほぼ全部がこれでした。

対策は 2 つです。

1. **一時 HTML を小さく保つ**。mermaid 本体（2.5MB）を埋め込むのをやめて参照にし、画像も base64 で埋め込まず元の場所を指す `file:///` URL を渡すようにしました
2. **前回と同じ内容なら、そもそも書かない**。組み立てた内容の MD5 を小さなハッシュファイルに残しておき、一致したら一時 HTML に触りません

| 場面 | 一時 HTML の書き直し | 実測 |
|---|---|---|
| 同じ文書を開き直す | しない | 約 60ms |
| `.md` を編集した後 | する | 約 100ms |

判定に**一時 HTML 本体を読み直してはいけない**、というのがもう一つの落とし穴でした。読み直しもまた検査待ちに巻き込まれて 2 秒かかります。判定は小さなハッシュファイルだけで行います。

## AI が書き換えるのを眺めたいとき

右クリックから開いた場合は、生成時点のコピーなので自動更新しません。

ただし `index.html` を直接開いて「フォルダ」ボタンから読み込むと、File System Access API のハンドルを保持するので、**外部からファイルが書き換わると 1 秒以内に再描画します**。Claude Code などに設計書を書かせながら、隣のウィンドウで整形済みの結果が育っていくのを眺める、という使い方はこちらです。

## できないこと

正直に書いておきます。

- **生の HTML は表示しません**。安全のため全部エスケープしています。通すのは `br` `kbd` `details` など一部のタグだけで、しかも属性は捨てます
- 図のピンチズームは未対応です。マウス操作を前提にしています
- 編集はできません。**読む専用**です
- Windows 専用です

## おわりに

「Markdown を読みやすくする」ツールはたくさんありますが、**ソースを一切変更しない・何も常駐させない・追加インストールが要らない**という条件を全部満たすものが手元に見つからなかったので作りました。同じ制約で困っている方がいれば使ってみてください。

設計上の判断とその根拠は、リポジトリの `docs/DESIGN.md` に実測値付きでまとめてあります。
